# Software Process
## Software Specification
- Software specification/requirements engineering adalah proses memahami dan mendefinisikan **what services** yang diperlukan dari sistem dan mengidentifikasi **constraints** pada operasi sistem dan development
- Berfokus pada **what to build**
- Phases/activities:
	- Req elicitation and analysis
	- Req specification
	- Req validation
- Specification role: software analyst
## Software Development
- Software development adalah proses **designing** dan **programming** **excutable system** di *deliver* kepada customer
- Berfokus pada mengimplementasi software design menjadi bahasa pemrograman yang ditentukan untuk membuat **excutable system**
- Software design adalah sebuah deskripsi dari struktur software yang akan di implementasi, data model dan struktur yang dipakai sistem, interfaces antar komponen sistem, dan kadang algoritma yang dipakai
- Berfokus pada **how to build**
- Phases/activities:
	- Architectural design
	- Data design
	- Interface design
	- Component design
- Design role: software designer
- Programming role: software programmer
## Software Validation
- Software validation (verification and validation) adalah proses untuk menunjukkan bahwa sistem sesuai dengan spesifikasinya dan memenuhi ekspektasi system customer
- Berfokus pada **finding bugs and errors**
- Strategies/stages:
	- Unit testing
	- Integration testing
	- Validation/requirements testing
- Techniques:
	- Black box testing
	- White box testing
- Software validation role: software tester
## Software Evolution
- Software evolution (software maintenance) adalah proses mengubah software selama masa pakainya setelah delivery sebagai response terhadap evolving requirements dan customer needs 
# SDLC Models
- SDLC adalah runtutan fase yang memberikan common understanding dalam proses software-building
- SDLC model adalah simplified representation of a software process
- Setiap model represents sebuah proses dalam perspective terentu (context)
# Waterfall Model
- ![[Pasted image 20241005155355.png]]
- Definisi: model yang sifatnya linear dan berurutan, setiap tahap harus selesai sebelum melanjutkan ke tahap berikutnya
- Kelebihan: sederhana
- Kekurangan: sulit adaptasi sama perubahan
- Usecase: projek kecil yg jelas
# V Model
- ![[Pasted image 20241005155524.png]]
- Definisi: model yang berfokus dev dan test
- Kelebihan: kualitas terjamin
- Kekurangan: req harus tau diawal
- Usecase: req lengkap
# Prototyping Model
- ![[Pasted image 20241005155539.png]]
- Definisi: model yang membuat prototipe awal untuk mendapat feedback
- Kelebihan: user terlibat
- Kekurangan: nambah biaya buat bikin prototipe 
- Usecase: user blom ada pengalaman
# Spiral Model
- ![[Pasted image 20241005155606.png]]
- Definisi: model yang fokus dengan manajemen resiko
- Kelebihan: resiko terkelola dengan baik
- Kekurangan: mahal dan rumit
- Usecase: besar mahal dan high risk
