# Pengertian Software
- Program komputer dan dokumentasi terkait seperti persyaratan, model desain, dan manual pengguna
- Software bisa generik (buat umum) bisa custom (spesifik)
- Software baru dapat dibuat dengan men-develop program baru, konfigurasi generic software system, atau menggunakan exsisting software
# Karakteristik Software
- Bisa direkayasa, bukan di fabrikasi/diproduksi
- Tidak mengalami keausan (wear out)
- Sebagian besar software itu customized
- Tidak bisa diraba (intangible)
# Pengertian RPL
- Menurut Roger S. Pressman, RPL adalah teknologi yang meliputi **proses**, sekumpulan **metoda** dan sederet **alalt bantu** untuk pengembangan software
- Menurut IEEE Standards Collection, RPL adalah penerapan sebuah pendekatan yang **sistemik**, **tertib**, dan **terukur** terhadap pengembangan, pengoperasian, dan perawatan perangkat lunak
- Menurut Fritz Bauer, RPL adalah penerapan **prinsip-prinsip keteknikan/rekayasa** dalam rangka memperoleh software yang **ekonomis** tetapi **andal** dan cukup **efisien** berjalan pada mesin yang sesungguhnya

# Kualitas Software
## Popular View
- Dapat dirasakan dan dinilai, tetapi tidak terukur
- Lebih dipengaruhi oleh persepsi, bukan fakta
## Professional View
- Terukur
- Berdasarkan atribut kualitas dan fakta
## Definisi Kualitas Software
- Menurut Philip B. Crosby pada 1979,  kualitas software adalah *the degree to which a system, component, or process meets specified requirements.*
- Menurut Joseph M. Juran pada 1988, kualitas software adalah *the degree to which a system, component, or process meets customer or user needs or expectations.*

## Faktor Utama Kegagalan Software
- Kebutuhan customer tidak bisa dipahami dan ditangkap dengan tepat
- Kebutuhan customer sering mengalami perubahan
- Customer tidak bisa bekerja sama dengan pengembang
- Pengembang kurang memiliki kecakapan dalam menjalankan tugas
- Sistem yang dikembangkan tidak terlalu banyak memberikan manfaat kepada customer
