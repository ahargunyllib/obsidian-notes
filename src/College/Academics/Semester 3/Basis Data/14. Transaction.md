# Transaction
- Satu kesatuan unit eksekusi tugas
- Apabila suatu transaksi berhasil, maka semua modifikasi akan di-*commit* dan semua perubahan disimpan secara permanen
- Apabila tidak berhasil, maka semua modifikasi akan di-*rollback* dan semua perubahan dihapus.
- Singkatnya, jika terjadi kesalahan ditengah-tengah, maka perubahan sebelumnya dihapus dan perubahan setelahnya tidak dieksekusi
- Transaksi akan selalu menunggu *commit* atau *rollback*
- *Commit* digunakan untuk menyimpan perubahan secara permanen
- *Rollback* digunakan untuk menggagalkan perubahan yang dilakukan transaksi, sehingga menjadi ke keadaan semula sebelum terjadi transaksi
- Contoh 
```sql
BEGIN TRANSACTION
	DROP TABLE users;
-- Menyimpan penghapusan table
COMMIT TRANSACTION;
-- Menggagalkan penghapusan table
ROLLBACK TRANSACTION;
```

# Nested Transaction
- Suatu blok transaksi baru dapat dijalankan meskipun blok transaksinya belum selesai
- Caranya dengan membuat `BEGIN TRANSACTION` di dalam `BEGIN TRANSACTION`
- `@@TRANCOUT` adalah variabel di server untuk menyimpan tingkat kedalaman nesting
- Ketika transaksi *explicit* dibuat, maka variabel otomatis bertambah
- Ketika dilakukan *commit*, maka variabel otomatis berkurang
- Ketika terdapat *rollback*, maka variabel akan menjadi 0
# Error Handling
- Seperti `try catch` pada umumnya
- `@@ERROR` atau `ERROR_NUMBER()`: mengetahui kode error
- `ERROR_MESSAGE()`: mengetahui pesan error
- Contoh
```sql
BEGIN TRY
	DROP TABLE users;
END TRY
BEGIN CATCH
	PRINT ERROR_MESSAGE
	PRINT 'Kode error = ' + CAST(@@ERROR AS NVARCHAR(255))
END CATCH
```
# Error Handling dalam Transaksi
- Dengan cara ini maka dapat dipastikan suatu transaksi apabila berhasil akan di-commit, bila tidak maka gagalkan dengan di-*rollback*
- Contoh
```sql
BEGIN TRANSACTION
BEGIN TRY
	DROP TABLE users;
	COMMIT TRANSACTION;
END TRY
BEGIN CATCH
	ROLLBACK TRANSACTION;
END CATCH
```
